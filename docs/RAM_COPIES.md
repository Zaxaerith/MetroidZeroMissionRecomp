# Required ROM-to-RAM integration metadata

OBSERVED_RAM_IMAGES.json records the nine previously verified ROM-to-IWRAM
images, full-image hashes, placements and lifecycle limits. Two stable images
are represented in game.toml; seven moving-stack bodies are regenerated by
tools/generate_stack_variants.cpp during the host build.

Production integration keeps guest RAM addresses and Thumb mode, full live-image
identity checks, active-image/IRQ context, and iterative stack-tail continuations.
Unrecognized or overwritten images use explicit fallback. These guards are
production behavior, not temporary instrumentation, and survive final cleanup.
No generated body is maintained by hand and no decomp implementation is copied.

Historical trace/dump path fields in metadata are provenance identifiers only.
The raw research artifacts and inspection scripts were retired. They are not
prerequisites for regeneration or smoke acceptance. Regeneration reads the
verified user ROM and configuration, not old RAM dumps or cached generated C++.
